# 思维导图生成性能重构设计

## 意图与证据

用户反馈 6 分钟仅处理 10/42，要求参考 NotebookLM 重新分析并优化。用户已经选择“完整导图一次生成”：生成完成后所有分支已存在，展开/收起不再调用模型。继续使用单篇文档、右侧直接编辑、应用内全屏和现有 simple-mind-map。

只读诊断：任务 126，来源文档 34 / 版本 33 / 索引 37；532 子块、167 个父块，父块原文约 153,671 UTF-8 字节；旧策略 42 组，多数组 2–5 KB。未识别出章节标题，按页标签阻止跨页拼组。任务已由用户取消，保持取消状态，不自动恢复。

同索引已保存的 12 个成功局部导图缓存共 523 节点、约 37.5 KB JSON，而最终整图限制 300 节点，说明中间阶段已经产生大量最后还需重新压缩的结构。仅凭旧进度和缓存不能还原每次 API 的耗时及失败原因，新版本需补充不含正文的调用指标。

Google 官方将导图定位为基于来源的主题概览、相关概念及层级分支，支持缩放、折叠和节点追问。没有公开具体 Prompt、模型调用数量、缓存策略、Map-Reduce 或布局库；引用聊天属于工程分析，不能作为 Google 内部实现证据。已通过用户现有 Chrome 页面只读核对其导图。

## 方案选择

- **已选择：自适应完整生成。** 可容纳原文时一次模型调用生成全树；长文按预算打包、并发提炼短要点，最后统一生成全树。保留全部原文参与处理，不以 TopK 或截取前文提速。
- 未选择：先生成浅层概览、展开时继续请求 AI。首屏较快，但改变展开全部、编辑和导出语义，等待与费用转移到展开操作。
- 不采用仅把旧 42 个局部导图请求并发化：仍重复生成树、保留过多输出及后续反复合并开销。

## 生成流程

1. **整理输入**：提取有序、去重的全文父块；保留章节、页码、内容类型（原生文本/OCR/表格/图解），无父块元数据时按来源范围去重。页码和小标题为模型提供上下文，不作为每次调用的硬边界。避免重新解析 PDF。
2. **选择路径**：使用现有 TokenizerService 对完整 Prompt（含来源标签和 JSON 指令）计数，预留生成输出与 1,024 安全预算。全文能容纳则直接生成最终树，不先调用模型摘要。尊重 CHAT_CONTEXT_TOKENS 和 CHAT_TOKENIZER，不擅自增加模型上下文或把估算值当真实 tokenizer。
3. **长文打包**：每批输入目标上限 24,000 预算单位，实际还需满足上下文、提示词、输出和安全余量。顺序填充跨页/跨小节；单块过大才拆窗。每个原文范围恰好进入一批，全部批次参与生成。
4. **并发提炼**：新增导图专用的精简要点结构（主题、核心要点和必要条件），不生成 simple-mind-map 树，不携带主题/样式/布局。每批输出最多 min(2,048, CHAT_OUTPUT_TOKENS)，主题数量随预算限制为最多 8 个，每主题最多 3 条短要点；简短节点标题只在最终阶段构建。对支持切换的模型显式请求非思考模式，普通聊天行为保持不变。默认并发 3，可用 MINDMAP_CONCURRENCY 配置为 1–4；并发属于同一个生成任务，保留队列任务并发 1，按来源顺序收集结果。
5. **一次成图**：最终阶段读取所有精简要点，归并语义主题和父子关系，生成简洁完整的知识树。输出使用紧凑的 text/children 格式，服务端转换为现有 v2 的 data.text/children。默认目标约 80–120 节点，仍遵守最多 300 节点、5 层；最终输出最多 min(4,096, CHAT_OUTPUT_TOKENS)。
6. **超长兜底**：如果全部要点仍无法放入最终 Prompt，只压缩这些要点，按预算形成层级归并，最多 4 轮；每轮必须减少总体输入体积，否则明确失败。不得裁掉整组原文、无限递归或在超预算时硬发请求。

约 154 KB 的本次样本，预计由旧 42 次章节模型请求缩减为约 7–8 次要点请求与 1 次最终成图；分组数以完整 Prompt 实测为准，结构错误修复、压缩和服务商限流可能增加调用，不承诺固定秒数。

## 生命周期、缓存与兼容

- 保留现有 API、存储 schemaVersion=2、用户/知识库权限、来源快照、模型绑定、任务幂等、租约和原子发布。页面侧栏/全屏/编辑交互不重写。
- 拆分纯输入规划与模型生成逻辑，避免继续扩大 MindMapsService；服务负责受理、进度、取消和事务落库，规划器负责去重/打包/预算，生成器负责直接生成/要点提炼/汇总与校验。
- 提炼、归并、最终树使用独立缓存命名空间与提示词版本 mindmap-v3.1。缓存绑定用户、知识库、来源版本、索引、模型身份、阶段、输入摘要。旧缓存和旧导图不删、不误作新要点缓存；失败重试只补当前版本下未成功的阶段。
- 多批并发的进度与指标写入保持事务锁和执行令牌校验，防止完成数倒退或旧执行者发布。成功/失败分别统计，不把“处理了”误写成“成功”。任一必要批次失败则不发布残缺导图。
- 普通批次失败继续收集其余批次成功缓存；取消、来源变化、失去执行权或鉴权失败则停止调度并 abort。所有在途 Promise 必须 settle 后，才结束任务并清理心跳/取消轮询，不能因 Promise.all 首次拒绝提前退出。缓存写入按“知识库→文档→任务”事务锁原子校验运行状态、执行令牌和来源快照。
- 每次发模型请求及写缓存/结果前校验执行权。每个活动任务共享 AbortController；在途请求传递 signal，跨进程通过周期性检查取消/来源变化中止后续工作。取消不能保证服务商不计已接收请求的费用。
- 每次调用保留最多一次结构修复。超时、鉴权及限流错误不伪装成 JSON 错误重试；429 遵守服务商重试提示并有限重试（最多 2 次，无法合理等待则给出限流错误）。保留成功批次缓存。没有取消授权的活动任务不得被本次部署主动取消。
- 旧任务没有新流水线字段时，在 Worker 重新领取后重新规划，重置阶段进度并使用新缓存空间；有有效租约的旧执行者不得被重复领取。已取消的任务（包括 126）不重新执行。

## 进度与诊断

沿用 stage/completed/total，直接路径显示“生成完整导图”；长文显示“提炼要点 x/y”，然后“整理全局结构”“校验导图”。不把提炼批次比例当成整个任务完成百分比，不编造剩余时间。

安全任务响应新增 mindmapProgress：strategy、modelCalls、cacheHits、startedAt、elapsedMs。每次模型调用记录阶段、耗时和可用的 token usage；不记录原文、Prompt、密钥或模型输出。全树默认仍按原有展开状态展示，不把折叠冒充尚未生成。

modelCalls 统计实际服务商请求：response_format 不支持后的兼容回退、结构修复和限流重试都计入。在 LlmService.complete 的每次实际 invoke 处提供可选的调用观察，不仅统计最外层 complete；其他业务调用保持原有行为。“短文一次调用”仅指服务商正常支持参数且输出有效的首次成功路径。TasksService 安全呈现和前端 ProcessingTask 类型同步增加新字段；进入全局整理/校验时清空旧 completed/total，避免一直展示提炼阶段的 7/7。

## 验证与验收

- 先写失败测试：短文首次只调用 1 次且没有提炼；42 页各不足一批上限时可以跨页打包，约 154 KB 的合成夹具不超过 8 个提炼批次；全文尾部、OCR、表格/图解输入均可观察到，去重不丢来源范围。
- 用确定的延迟模型验证并发峰值为 3、配置 1 时串行、结果顺序稳定、并发完成数不回退、最终生成只发生在全部要点成功后。
- 检验完整 Prompt 计数、极小预算拒绝、超大父块拆分、最终输入超限压缩、不收敛失败、JSON 修复次数、调用次数上界、429 有限重试和取消后不再调度。
- 保留旧数据、版本变化、删除期间保存、跨用户隔离、缓存和请求幂等的既有测试；新增并发期间取消/删除/更新的测试。
- 前端验证新阶段文案和刷新恢复，右侧/全屏/展开全部/收起全部/保存/导出回归。前后端构建、后端全量测试、相关 API 与浏览器测试正常退出。
- 性能先以相同输入的调用数、并发度、输入/输出规模和阶段耗时衡量。只读本地真实数据用于计算规划统计，不将私人原文自动传送至外部服务。真实模型质量与延迟测试需使用用户明确授权的资料/目的地，或非敏感合成输入；报告实测值，不能以 mock 延迟承诺实际提速。
