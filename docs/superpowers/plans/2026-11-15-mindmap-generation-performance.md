# 思维导图生成性能实施计划

> 使用 superpowers:subagent-driven-development 按任务实施。用户已确认设计并授权直接实施，不再重复请求确认。

**Goal:** 将按页串行生成局部导图改为自适应完整生成，减少请求与中间输出，并保留现有编辑能力。
**Architecture:** 短文直接全树，长文按全文预算打包、默认三路提炼精简要点，最后一次生成完整树。保留任务所有权、模型快照、租约、版本校验和 v2 数据；新增 mindmap-v3.1 阶段缓存。
**Tech Stack:** Vue 3、NestJS、现有 TokenizerService/LlmService、MySQL/BullMQ、simple-mind-map。
**Spec:** ../specs/2026-11-15-mindmap-generation-performance-design.md

## 约束与接口

- 原改动均保留，工作在已有 codex/mindMap-refactor 分支，不清理/还原用户文件，不自动提交或推送。
- 继续单篇文档、完整树、最多300节点5层；展开不调用AI；不恢复已取消任务126。
- ModelExecutionOptions 新增可选 onAttempt(event): Promise<void>|void；事件为 {phase:'start'} 或 {phase:'end',status:'success'|'error'|'cancelled',elapsedMs,usage?}，不包含原文、输出、URL或密钥。每个实际 invoke 触发一次start/end，兼容回退同样统计。
- 任务安全呈现新增 mindmapProgress:{strategy:'direct'|'batched',modelCalls,cacheHits,startedAt,elapsedMs,failedBatches?}。新阶段generating=生成完整导图、mapping=提炼要点、merging=整理全局结构、validating=校验导图；非提炼阶段total=null/completed=0。
- 并发错误需要等待所有在途请求settle。守卫、缓存与发布分别在正确事务边界检查执行权。整个Prompt计数，预留对应输出和1024安全预算。

## Kimi 生成失败验收修正

- 用户报告任务 127 的 7 个批次全部失败、实际调用 14 次。只读模型快照确认该任务使用账号配置的原生百炼 `kimi-k3`；此前真实验收使用 `.env` 的默认 Qwen，未覆盖用户账号模型。
- 使用纯合成资料和同一 Kimi 配置定位：默认思考模式达到 1,024 输出 token 上限；关闭思考后同份资料有效返回。更丰富的 42 页合成资料在关闭思考后仍有 2/7 批触及旧上限，因此同步限制要点数量和长度，将提炼上限调整为 min(2,048, CHAT_OUTPUT_TOKENS)。提示词版本升为 `mindmap-v3.1`，防止混用旧生成缓存。
- 先写本地 HTTP 适配器回归，观察缺少思考开关、密集要点预算不足、错误原因被隐藏及零成功错误提示缓存的失败；修复后通过。普通聊天保留默认行为，思考专用 Kimi 路由不收到不支持的参数。JSON 二次解析失败使用安全分类，截断与传输失败不进入 JSON 修复；保留全部在途请求收尾、成功缓存和重试机制。
- 长文实测：同账号 Kimi，42 页、143,147 字节的虚构站点手册，7 次提炼 + 1 次成图、峰值并发 3，约 27.9 秒生成 96 节点、4 层完整导图。短文实际 1 次请求，约 5.6 秒。文本为合成资料且重复度较高，这些耗时不代表真实 PDF 的延迟保证。未修改业务数据库，未重复上传用户 PDF。
- 独立代码审阅未发现重要问题；Kimi、LLM、engine、v3、generation、races 共 39 项独立回归通过。原并发测试的 1,800 字章节因提示词增加而触发拆窗，将该测试上下文设为 4,608，保留原 8 批、并发峰值、稳定顺序及最终单次成图的全部断言。
- 最终检查：后端构建、80 套 475 项全量测试、18 项 API e2e，以及本次代码的 Prettier 检查均正常退出通过。API e2e 中另外两套外部集成测试按现有配置跳过（19 项）。本次未修改前端。
