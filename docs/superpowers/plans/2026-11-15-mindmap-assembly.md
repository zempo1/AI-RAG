# 知识点复用与程序组树实施计划

> **For agentic workers:** 使用 superpowers:executing-plans；独立的用量展示任务按 dispatching-parallel-agents 并行处理。

**Goal:** 保留均衡学习导图与快速展开，消除最后一步重复输出全文节点导致的截断。
**Architecture:** 长文保持全文分批提炼和旧提炼缓存，给主题分配稳定 ID；模型只返回标题和主题 ID 分组，程序复用原始要点组树。短文保留一次生成，输出截断时退回提炼组装。全量数据随打开导图载入，初始折叠细节，展开无需等待服务端。
**Tech Stack:** NestJS / TypeScript / Vue / simple-mind-map。
**Spec:** 用户本聊天已确认的“均衡学习版＋知识点复用＋程序组树＋节点预取”方向。

## 全局约束与决策
- 在现有 codex/mindMap-refactor 分支续作，保留所有未提交修改，不自动提交、推送或改业务数据库。
- 不新增昂贵的展开调用和详情扩写功能；300 节点内直接预载完整树比拆网络接口更快，仍满足节点预取目标。
- 新 pipeline 为 mindmap-v4；extract/compress 保留完全相同的 v3.1 提示词及缓存键，以复用当前失败任务的七批提炼成果；新 organize/direct 单独版本。
- 组织接口为 {title:string,groups:[{title:string,ids:string[]}]}，不接受生成事实文本。每个有效主题 ID 必须恰好出现一次，未知/重复/遗漏均判无效。
- 组织结构失败允许一次修复；输出截断或预算不足则按来源顺序本地分组，记录组织回退。网络、权限及取消错误照常传播。
- 程序仅去除相同主题下完全一致的要点，不模糊合并数字/否定/条件。最多300节点5层；极长文按主题/要点轮转选取，记录省略数量，不把处理完成描述为所有事实完整保留。
- 不自动向外部服务发送真实PDF；可只读真实缓存并本地组装验收。

## Review Focus
主题ID遗漏/重复；不同数字条件被去重；最终截断重跑原文；旧缓存版本混用；usage缺失或失败请求丢账。上述情况分别纳入核心和用量测试。
