# 多知识库与异步 RAG 实施清单

> 使用 executing-plans 连续实施，业务逻辑先写失败测试再实现。

**Goal:** 实现用户私有知识库、库内分类、异步解析与向量索引、文件版本更新和答案引用。

**Architecture:** NestJS API 与 Worker 独立进程，共用 MySQL 业务记录与原件目录；Qdrant 仅检索已发布的索引版本；Redis/BullMQ 调度幂等任务。Vue 管理知识库并轮询任务，聊天 SSE 返回最终答案与引用快照。

**Spec:** 用户在本聊天确认的完整方案（2026-10-31）。

## Global Constraints
- 用户与知识库双重隔离，先过滤后 TopK。
- 同文档最后接受的提交为目标，失败保留已发布版本。
- 删除前开始的问答允许完成；删除后的请求不可检索来源。
- 文本 PDF/Markdown；一级分类；文件级增量；模型维持 MiniLM 384。
- 显式升级数据库，不启动自动 DDL；旧文档页码未知。
- 不执行用户现有数据库迁移；集成测试使用独立测试数据库。

## Review Focus
- 队列投递遗漏、重复执行、进程中断与迟到发布。
- 删除任务与进行中的批次写入竞态。
- 全库重建锁释放及部分失败。
- 流式引用规范化与历史答案一致。
- 无原件遗留数据、JSON/ID 数据库映射和派生产物版本。
