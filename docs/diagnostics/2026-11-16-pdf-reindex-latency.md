## 现有链路与问题

1. MySQL 保存任务和模型快照，BullMQ documents 队列投递；单个 Worker 的该队列并发为 1。
2. PDF.js 逐页提取原生文字和几何；自动分流到原生结构、本地 Paddle 布局/OCR、远程视觉图解。
3. 页面窗口最多 3 页，必须按页码取出结果；窗口按消费进度补充。前面一页慢时，后面两页即使已完成，也不能持续补充新页，造成队头阻塞。视觉并发为 3 不等于全过程一直有 3 个有效请求。
4. 单区域视觉的 180 秒总期限从进入调度前开始，包含排队、请求、瞬态重试及格式修复。一个请求耗尽期限后，瞬态重试基本已没有可用预算。
5. 区域失败会阻止继续派发新请求，并等待已发页面工作收敛，错误上抛到整个索引任务；BullMQ 再次执行整篇。
6. 成功区域及 embedding 批次已有缓存，因此不等于每次重试都重新付费识别全文。但重试仍从头遍历，重新分块；已有隐藏版本向量先删除，再写回。
7. 解析与分块、embedding、写向量已进行流式重叠；不应把它误改成整篇解析结束才开始 embedding。
8. 全部完成且向量可查询后，事务发布新索引；旧索引延迟清理。完整发布语义应保留。

## Worker 锁失效与本地服务

本地安装的 BullMQ 默认锁时长 30 秒、续租周期约 15 秒、stalled 检查周期 30 秒。这里的 30 秒是可续租的锁，不是“任务必须 30 秒完成”。异步等待远程 API 本身不应使锁失效。

当前 Worker 子进程启动时间为 10:47:21，处于任务进行期间；启动方式是 `node --watch dist/worker.js`。已有明确的 stalled 事实和中途启动进程的证据，但没有完整进程退出日志，不能区分手动重启、watch 重启、异常退出或事件循环/Redis 阻塞的全部贡献。

PDF 容器在 10:47:22 记录 Paddle 子进程收到 SIGTERM，发送方是父进程 PID 1。Python 服务的超时/断连恢复逻辑会主动终止并重建推理子进程；此日志与该路径相符，不等于 OOM 或 Paddle 自发崩溃。缺少对应 request ID 和操作耗时，不能把这一次终止确认为四次远程视觉失败的原因。

任务基础层当前会在 SQL 未终态而 Redis job 已 failed/completed 时删除并重建 job。stalled 失败不一定走过业务处理器的失败写回，因此可能重置 Redis 的重试计数，增加实际执行次数。应给此路径独立的持久恢复计数、租约和退避，而不是不断以新 job 掩盖失败。

## 建议的优化顺序

### 优先级一：任务可靠性与可观测性

- 长时间重建使用稳定 Worker 进程，避免开发态 watch 在运行中重启；优雅关停停止接新任务并等待当前工作或持久交接。
- 索引任务增加 SQL 原子领取租约、心跳和恢复代数；stalled 重投受持久次数和退避约束，不能仅靠重新创建 Redis job 重置次数。
- 日志和任务尝试历史统一关联 taskId、documentId、attempt、page、region、provider request ID；区分排队、发出、首响应、完成、取消原因和 token usage。
- 记录事件循环延迟与续租失败；确认确有 CPU 阻塞后，把重渲染/几何工作移到线程或隔离进程。不要仅提高 lockDuration 掩盖异常。

### 优先级二：区域级恢复，避免慢区域阻断全文

- 把页面发现、区域识别、按序组装拆开；用有内存上限的就绪队列，某区域失败/等待重试时，继续处理其余可执行区域。
- 成功结果立即持久缓存；失败区域延迟进入独立重试集合，给其他工作释放配额。最后补齐失败集合，全部满足后再发布完整索引。
- 区分排队期限、单次请求期限和区域总预算；按实际延迟分位数设置参数，例如单次 45–60 秒、一次瞬态重试作为待验证起点，而非未经实测直接替换 180 秒。
- 超时、429/Retry-After、502/503/504、非法 JSON、长度截断分别处理；长度截断应调整输出预算或分割区域，不能原样格式修复。
- 保留首个根错误和取消来源，避免只显示 `Request was aborted.`。
- 取消/来源变更仍立即停止；任一必须区域最终失败仍不得静默发布残缺全文。

### 优先级三：解析与索引分离、可恢复检查点

- 增加页面/文档解析产物缓存，键覆盖来源 hash、文档版本、解析器/提示词版本、本地模型 manifest、视觉模型/服务标识。
- 同源同解析配置仅重建向量索引时，直接使用解析产物，不再逐页渲染和图解。修改视觉模型或解析规则则重新解析。
- 跨页表格处理后再冻结相应页面产物，保留原文位置、图像引用与权限隔离。
- 隐藏索引保存批次内容 hash、完成状态与稳定分块 ID；只补缺失/变化批次，最终校验并清理尾部，避免失败一次就 removeRevision 全量重写。

### 优先级四：受控调度和模型输出

- 在区域级恢复、共享配额和检查点具备后，允许两个文档公平交错执行；远程视觉仍按账号/供应商共享并发与速率限制。本地 Paddle 单进程要独立背压。直接把 documents 并发从 1 改成很多可能更慢。
- 普通图解使用紧凑、明确的结构化输出；以本次长度分布为依据试验 1536–2048 token 起步预算，复杂表格/密集图按需升档。不能统一降低后截断内容。
- 视觉模型是否更换，应对同一批局部图做准确率、P50/P95、超时率和成本对比，尤其核对箭头方向、数值和表格关系；没有证据支持“换更大模型一定更快”。

## 验收方式

- 离线注入某一区域长时间无响应，验证其他页面继续完成，仅失败区域重试，成功区域不重复请求。
- 模拟 Worker 退出、stalled、重复投递和重启，验证唯一有效执行、恢复计数不重置、结果只发布一次。
- 在来源、模型与解析配置完全不变时重新索引，验证视觉请求数为 0；只重做必要的分块/embedding/索引步骤。
- 对照两份 PDF 冷缓存、热缓存各自记录总耗时、排队耗时、真实调用数、缓存命中、P95、失败区域、token 与最终内容覆盖。
- 保留跨页表格、原文坐标、图解和原子发布的既有测试。
