# 思维导图

在文档管理中选择已完成索引的 PDF 或 Markdown，打开工作台的「思维导图」标签并点击生成。生成采用后台任务，可以继续聊天或阅读 PDF；重新打开工作台或刷新页面后可以找回任务。

## 生成与来源

每次任务固定提交时的文档版本、索引版本和模型设置。正文、OCR、表格与图解已有解析文字均参与处理。短文直接生成均衡学习导图，不强凑节点数；输出截断时退回提炼与组装。长文按输入预算跨页打包，默认三路并发提炼要点；服务端为主题分配 ID，模型只输出主题 ID 分组，程序复用原始要点文字组装完整树。最后一步不再重复发送、改写全部知识点。处理完成表示全文参与生成，不保证每个原文细节均保留在导图中。

主题分组要求每个 ID 恰好出现一次。分组输出截断、一次格式修复后仍无效，或目录超出预算时，程序按来源顺序组织已提炼内容，并在导图中提示。鉴权、网络与取消错误仍正常报告。仅合并相同主题内完全一致的要点，保留不同数字及条件；超长资料按主题和要点轮转选取以满足最多 300 节点、5 层，并明确提示部分细节未展示。

如果有章节失败，任务不会发布不完整的导图。错误信息区分输出截断、JSON 结构错误、限流和服务异常，并显示实际成功缓存的批次数；重试会利用当前生成版本下已经成功处理的分组缓存。来源文档或索引在任务执行中改变时，需要基于当前来源重新生成。无有效索引的旧资料需要先重建索引。

任务区显示「生成完整导图」「提炼要点」「整理全局结构」「校验导图」等阶段，并列出实际模型请求次数、应用缓存复用次数、累计耗时及服务商返回的输入/输出/总 token。用量按当前流程版本累计，包含同版本重试，不含旧流程的历史消耗；旧任务与缺失 usage 的请求明确显示未知，不以零冒充。应用缓存复用表示跳过模型调用，不代表服务商计费缓存折扣。提炼阶段的 x/y 仅代表成功提炼批次，不是整个任务的完成百分比。结构修复、兼容 JSON 参数回退和限流重试也计入实际请求次数。

`MINDMAP_CONCURRENCY` 默认 `3`，可配置为 `1` 至 `4`；发生限流时可以降低。更改部署配置后需要重启 API/Worker。输入预算继续遵循 `CHAT_CONTEXT_TOKENS` 和 `CHAT_TOKENIZER`；默认 `estimate:utf8-v1` 是保守的 UTF-8 字节估算，不是服务商真实 tokenizer。提炼及 ID 分组最多输出 2,048 tokens，短文直接成图最多输出 4,096 tokens，均不超过现有 `CHAT_OUTPUT_TOKENS`。提炼提示词按预算限制主题数量（最多 8 个），每主题最多 3 条短要点。每次请求还会预留提示词和安全空间。

导图结构化生成对支持切换的模型显式请求非思考模式，避免思考过程占用有限输出预算；普通聊天继续沿用原行为。原生百炼 `kimi-k3` 支持此开关，思考专用的 `kimi/kimi-k3` 路由不会收到不支持的参数。

新流程及分组缓存使用 `mindmap-v4`；提炼提示词和预算保持不变，继续使用 `mindmap-v3.1` 提炼缓存，因此之前只在最终成图失败的任务可复用成功提炼成果。缓存仍绑定用户、知识库、文档版本、索引和模型身份。新版本不会自动恢复已取消的生成任务，需要用户重新点击生成。取消会停止新请求并尝试中止在途请求，但不能保证服务商不对已接收的请求计费。

生成使用「模型设置」中的对话模型。默认 Redis/BullMQ 模式需要 API 和独立 Worker 均运行；启动命令与共享配置见 [后端运行指南](../nestjs/README.md)。内存演示模式由 API 进程调度，重启后不会保留任务和导图。

## 阅读与编辑

工作台生成中仅显示动态阶段进度、预计剩余时间与取消入口。剩余时间按已完成批次速度或同知识库短文历史耗时估算，数据不足时显示估算中；不承诺精确倒计时。完成与取消的任务卡隐藏，完成结果进入历史记录；失败保留原因与重试。实际 token 仍由后端记录，默认界面不显示技术指标。

导图采用石墨青蓝深色主题，所有层级使用高对比浅色文字。布局通过支持键盘操作的主题菜单切换。

点击导图记录后在右侧直接编辑，聊天保持可见。点击全屏按钮扩大到整个应用，再次点击或按 Esc 返回右侧。窄屏使用侧边抽屉，不会自动进入全屏。

组装导图默认展开主干、折叠知识点细节。打开时已预载完整节点数据；首次展开与再次展开均在本地完成，不需要模型调用或分支接口等待。

- 「全部展开」显示所有层级，「全部收起」保留根与一级分支。
- 可以缩放、适应画布、切换布局、撤销与重做。
- 修改后点击保存；布局与折叠状态一起保留。关闭或切换内容时按提示保存或放弃修改。
- 导出支持 PNG。

展开、收起仅改变阅读状态，不触发未保存提示；文字、节点结构和布局修改仍会触发保存保护。主动保存时仍会一并保留当前折叠状态。关闭确认使用居中卡片，提供取消、放弃更改和保存并继续。

旧导图兼容历史节点格式；损坏内容会显示错误。来源更新后，历史导图会标记来源已更新，可以重新生成新记录。删除来源文档会按项目现有规则删除关联导图。

## 接口升级

`POST /api/mindmaps/generate` 接收 `{documentId,requestId}`，HTTP 202 返回 `{taskId,status}`，不再同步返回导图。`requestId` 用于重试同一次提交，新的生成意图使用新的 ID。

`GET /api/mindmaps/workspace?knowledgeBaseId=…` 返回当前知识库的 `{items,generationTasks}`；列表不包含完整节点树，打开记录后通过 `GET /api/mindmaps/:id` 按需读取。任务详情使用 `GET /api/tasks/:id`，完成后通过 `mindmapResult.mindMapId` 获取结果。

`PUT /api/mindmaps/:id` 继续使用 `{data:string}`。新数据采用 `schemaVersion:2`，包含 `root/layout/theme/view/meta`；来源和覆盖元数据由服务端维护。历史 `{root}`、裸节点树、`{nodeData}` 可读取，保存时转换为新格式。此次不增加数据库列，无需为导图单独运行迁移。
