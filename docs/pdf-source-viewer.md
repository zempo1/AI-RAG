# 原 PDF 阅读与引用高亮

知识库中的 PDF 文件和回答中的引用共用来源阅读器。桌面端保留聊天并展示 PDF；窄屏切换为全屏阅读，关闭后返回聊天。打开预览不改变问答筛选或工作台来源。

## 使用与旧资料升级

- 新上传或重新建立索引的 PDF 会保存来源坐标。点击回答引用时，阅读器打开回答所使用的文件版本，跳到证据页并高亮来源区域。
- 旧文档可在文档管理中逐份点击“重建”。系统不会自动批量重建，也不会改写已有聊天的引用快照。重建后产生的新回答才使用新坐标。
- 更新代码和前端依赖后，重启后端与独立 Worker，让新解析任务使用带锚点的解析器；不需要数据库结构升级。
- 已有引用没有坐标时，按原有页码定位并提示无法精确高亮；位置未知时展示文字快照。原件缺失或来源删除后，保留可用的引用快照和图片预览。
- 替换文件后，历史引用仍指向原版本；清理退休索引不会影响已保存的锚点和历史原件。删除文档或知识库后，原件读取立即被拒绝。
- Markdown 使用文本预览；刚上传且尚未建立索引时，可以从原件读取文本。

## 坐标与数据链路

原件始终保留原始版式。PDF.js 渲染页面；解析器为正文文本项、OCR 行、图表区域建立坐标锚点。原生文本和 OCR 使用文本项/行级框，图解或模型生成的表格描述使用对应图像区域，边界不保证逐字裁剪。

`SourceLocation.anchorVersion = 1`，`anchors` 包含 `page`、`start`、`end`、`rects` 和 `kind`。文本偏移是该索引最终解析全文中的 UTF-16 半开区间；页码从 1 开始。矩形是 PDF 固有旋转和 CropBox 对应 viewport 的左上角归一化坐标。阅读器通过 PDF 坐标中转，在用户缩放、旋转时同步变换高亮。

段落重排、图解插入、页间拼接、父子切块、Agent 截断和证据合并都必须同步裁剪或平移锚点。锚点保存在 MySQL 的 Chunk、父块位置和回答引用快照中；模型输入、历史预算计算及新写入的 Qdrant payload 不包含这些几何数据。

最终视觉解析缓存增加独立的 `geometryVersion`。旧的最终块缓存需要重新装配几何，仍然复用有效的原始 OCR/视觉识别缓存。

## 读取接口

- `GET /api/documents/:id/preview?versionId=...` 返回版本信息、MIME 类型、原件可用性与读取 URL。未指定版本时优先生效版本；首次上传未发布索引时选择最近已保存的版本。
- `GET /api/documents/:id/versions/:versionId/original` 返回原 PDF，支持单段 Range，响应为 `200`、`206` 或 `416`。
- `HEAD` 同一路径返回文件元数据，不返回正文。

所有读取都验证用户、知识库、文档和版本归属及删除状态。响应采用 `private, no-store`；原件不放到公共静态目录，元数据不暴露本机路径。浏览器使用授权头直接交给 PDF.js 加载，避免先下载整份 Blob。

前端构建需整体部署 `frontend/dist`，包括 `pdfjs/` 下的字体、CMap、WASM 以及 `assets/` 中的 Worker。阅读器按需加载，不依赖外部 CDN。

## 验证

在 `nestjs` 目录运行 `npm run build` 和 `npm test`；在 `frontend` 目录运行 `npm run build`、`npm test`、`npm run test:e2e`。自动测试使用固定 PDF 与确定性 OCR/模型边界，不调用付费模型。

真实资料核对时，选择一份混排 PDF 和一份扫描 PDF，逐份重建后提问，核对原生文字、OCR、图表区域的引用页与高亮；再检查旋转、缩放和旧版引用。实际 OCR 内容质量仍取决于配置的识别服务。
